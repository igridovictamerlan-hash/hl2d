# Новая система: чек-лист

Проект держится на нескольких соглашениях (CLAUDE.md, «Соглашения»), и новая механика ломает их тише всего:
магическое число в коде, система, забытая в тестовом мире, новый вызов общей случайности, который сдвинул два
десятка тестов, раздел в CLAUDE.md, которого нет. Иди по списку сверху вниз; живые образцы — `systems/Memorials.ts`
(небольшая система целиком) и `systems/Neighborhoods.ts` + `systems/Crowd.ts` + `config/crowd.ts` (поведение
жителей, выключенное в тестах).

## 1. Конфиг — `src/config/<тема>.ts`

Все числа, цвета, скорости, шансы, реплики — сюда, с комментарием по-русски: **что** значит параметр и **в чём**
(секунды, px, тайлы, доля). Объект `as const`, имя — заглавными (`HOODS`, `CROWD`). В коде — ни одного «магического
числа»; ключи конфига потом называются в CLAUDE.md в обратных кавычках.

## 2. Система — `src/systems/<Имя>.ts`

- Конструктор `(ctx: AiContext)`; флаг `enabled = true` и выход из `update` при `!enabled` — чтобы выключать в тестах
  и в «отряд на отряд».
- **Своя случайность**: `this.rng = ctx.rng.fork(0x…)` (уникальная соль). Общую `ctx.rng` новая система не
  трогает — иначе сдвинется весь мир и десятки сид-зависимых тестов.
- Логика без DOM и без API Node; к UI — через `ctx.bus.emit(…)`, новые события — в `GameEvents`
  (`src/core/EventBus.ts`). Строки журнала — `bus.emit('log', { text, kind })`, реплики — `Character.say`.
- Подписки на бой и гибель — `ctx.combat.deathListeners`, `onDamage` (цепочкой, не затирая чужие обработчики).
- Новая роль NPC — через `RoleSpec`/`spawnRole` (`systems/Roster.ts`) и `brainFor`; новое здание — генератор
  (скилл `map-preview`), POI в `PoiType` и проверка в `validateMap`.

## 3. Подключить

- `src/ai/AiContext.ts` — поле (`import type`, без циклов импорта значений).
- `src/core/Game.ts`: в литерал контекста — `null as unknown as …`, создание `this.ai.x = new X(this.ai)` в
  правильном месте (после систем, на которые опирается: `housing`, `combat`, `war`…), вызов `update` в тике
  (см. порядок в CLAUDE.md, «Тик логики»), выключение в `startArena` (`if (this.ai.x) this.ai.x.enabled = false`),
  отрисовка — в `Game.render` в нужном слое (без `save/restore`, градиентов и сборки строк в цикле по сущностям).
- `tests/simHarness.ts`: то же поле в литерале, создание и `update` в `step`. **Поведение, которое меняет жизнь
  города, в безголовых тестах выключено** (`ctx.x.enabled = false` сразу после создания) — старые тесты выверены на
  прежнем поведении; в `npm run worldstats` — включено (переменная `X=0` выключает, допиши в CLAUDE.md «Команды»).
- Выключенная система должна оставить мир **ровно прежним**: та же логика и то же число и порядок вызовов
  `ctx.rng`. Если правишь старый код (мозг, заселение), ставь проверку «включено?» после старых вызовов случайности
  или так, чтобы они вызывались в тех же случаях (`!rich && rng.chance(…)`, как в `Families`).
- Сохранение игрока или мира — `SaveGame` (`SaveData`, версия формата) — только если состояние должно пережить
  перезапуск.

## 4. Тест — `tests/<тема>.test.ts`

- `makeSim(12345)`, нужный состав (`spawnPopulation(sim.ctx, AI.citizens)` или вручную `createCharacter`), включить
  свою систему в тесте, прокрутить `sim.step()` и проверить исход.
- Ждать условие (`until`), а не «ровно N секунд»; сравнение «новое лучше старого» — с запасом и по метрике, которая
  отражает суть (образец — `tests/crowd.test.ts`).
- Долгие сценарии — таймаут теста (`{ timeout: 300_000 }`) и мысль о том, что полный `npm test` уже ~12 минут.

## 5. Замер

Строка в `tests/worldstats.test.ts` (счётчики `stats` системы) и прогон «до/после» — скилл `world-audit`; в браузере
— скилл `playtest` (скриншот, тик логики, ошибки страницы).

## 6. Документация и коммит

- CLAUDE.md: файл в дереве «Архитектура», раздел системы (как работает, ключи конфига, тест), упоминание в «Тик
  логики», если встала в порядок обновления, пункт в «Этапы» — что увидит игрок и замер «до → после».
- Тексты для игрока — названия своего мира (таблица в начале CLAUDE.md: Протекторат, ВС, Легион, Управа, ГЭС…),
  по-русски, без названий HL2.
- `npm run typecheck && npm test` (полный прогон в фоне, разбор падений — скилл `test-triage`), коммит в ветку
  задачи, пуш. Пользователю — короткий отчёт: что изменилось для игрока, цифры, картинка.
