# Замер живого мира

Тесты проверяют сценарии, но не отвечают на «как живёт город целиком». Для этого два безголовых замера — оба на
`tests/simHarness.ts`, без DOM, детерминированы по сиду, десятки игровых минут за минуты реального времени:

1. **`npm run worldstats`** (`tests/worldstats.test.ts`) — сводка всего мира: население, смерти «кто кого и как»,
   деньги и сытость по группам, чем заняты, кто стоит 30 с и «идёт, но стоит», закон, банды, подполье, фронт по КПП,
   блиндажи, рация, разговоры, живые люди, толпа, штат ВС. Состав — как в тестах (множитель населения 1, ~220 NPC),
   начало — с заката (`LIGHTING.start`, 17 ч), клетка толпы 8×8 (`CROWD.cell`).
2. **Тепловая карта толпы** (`scripts/density.viz.ts`) — где люди проводят день: средняя плотность по ячейкам 6×6
   тайлов, самая людная ячейка (все и только жители без задержанных), жители у площади **по часам** и **чем они там
   заняты**, горячие ячейки, зоны. Население — как в игре на «много» (`SCALE=4`, ~570 NPC), начало — 7 ч утра.
   Это то, что показывать пользователю картинкой.

Числа двух замеров напрямую не сравнивай: разный состав, начало суток и размер клетки.

## Как запускать

Из корня репозитория. Долгие прогоны — в фоне с логом, ждать завершения циклом в одном вызове Bash (timeout до
600000), а не `sleep` подряд:

```bash
mkdir -p /tmp/hl2d-audit
MINUTES=12 npm run worldstats > /tmp/hl2d-audit/ws_after.log 2>&1 &                          # ≈ 3–4 мин
TAG=after MIN=12 OUT=/tmp/hl2d-audit npx vitest run --config .claude/skills/world-audit/scripts/vitest.config.mjs density > /tmp/hl2d-audit/density_after.log 2>&1 &   # ≈ 3–4 мин
until grep -q "Test Files" /tmp/hl2d-audit/density_after.log; do sleep 5; done
```

Несколько прогонов можно запускать параллельно — это отдельные процессы. **Пока идут прогоны, не правь `src/`**:
vitest подхватывает файлы по мере импорта, и прогон смешает старый и новый код.

Переменные `worldstats` — в CLAUDE.md («Команды»): `SEED`, `MINUTES`, `RELATIONS=0`, `HOODS=0`, `CP=classic`,
`LINE=0`, `DUGOUTS=0`, `WARCFG="dugout.sortie.chance=0,line.shift=300"`. Тепловой карты: `SEED`, `MIN` (12 ≈ 16
игровых часов), `START` (час начала, 7), `SCALE` (4 = «много», 1 = состав тестов), `HOODS=0`, `CP=classic`,
`LINE=0`, `CELL`, `NEAR` (радиус «у площади», 50 тайлов), `MAXV`, `OUT`, `TAG`. Результат — `OUT/heat_<TAG>.png`
(площадь — жёлтая метка и круг «у площади»), `OUT/heat_<TAG>.json` (данные для общей нормировки) и
`OUT/density_<TAG>.txt` (сводка).

Строки `worldstats`, которые обычно нужны: `grep -E "Население при старте|Погибли|Убийцы|Как:|Занятия|Стоят на месте|«Идут»|Толпа:|Фронт|Живые люди|голодают" <лог>`.
Сытость и «голодают» печатаются раз в 5 игровых минут — при `MINUTES` меньше 5 их не будет.

## Сравнить

**Режим на одном коде** (районы, линия армии, тип КПП) — два прогона с разными `TAG`, тот же сид и параметры:

```bash
TAG=off HOODS=0 MIN=12 OUT=/tmp/hl2d-audit npx vitest run --config .claude/skills/world-audit/scripts/vitest.config.mjs density > /tmp/hl2d-audit/off.log 2>&1 &
TAG=on          MIN=12 OUT=/tmp/hl2d-audit npx vitest run --config .claude/skills/world-audit/scripts/vitest.config.mjs density > /tmp/hl2d-audit/on.log 2>&1 &
```

**До/после правки** — тот же замер на старом коде:

```bash
D=$(bash .claude/skills/world-audit/scripts/baseline.sh HEAD)      # или хеш коммита до правки; печатает путь рабочей копии
cd "$D" && TAG=before MIN=12 OUT=/tmp/hl2d-audit npx vitest run --config .claude/skills/world-audit/scripts/vitest.config.mjs density
cd "$D" && MINUTES=12 npm run worldstats > /tmp/hl2d-audit/ws_before.log 2>&1
cd /home/user/hl2d && git worktree remove --force "$D"              # вернуться в основную копию и убрать рабочую
```

`baseline.sh` делает отсоединённый `git worktree`, подключает `node_modules` ссылкой и кладёт туда скрипты скилла
(в старом коде их может не быть; скрипт замера переносит отсутствие новых систем). Если правка ещё не закоммичена —
`HEAD` и есть «до».

**Склеить для пользователя** — из JSON, тогда все картинки перерисуются с **общей** нормировкой цвета (максимум из
прогонов, шкала внизу); PNG на входе сохраняют свою нормировку и на глаз сравнивать их нельзя:

```bash
python3 .claude/skills/world-audit/scripts/compare.py --out /tmp/hl2d-audit/compare.png \
  /tmp/hl2d-audit/heat_before.json "ДО: <что было> — <главная цифра>" \
  /tmp/hl2d-audit/heat_after.json  "ПОСЛЕ: <что стало> — <главная цифра>"
```

`auto` вместо подписи — тег, живых, самая людная ячейка жителей и доля жителей у площади из txt. Цифры в подписи
бери из своих txt, не из примеров. Посмотри картинку сам (Read). Если с пользователем говоришь ты — отправь
(SendUserFile) с подписью, что сравнивается; если тебя запустили как помощника — верни путь.

## Как читать

- **У площади по часам** и **чем заняты** — толпа. Смотри строки «у площади N–M ч (всего …)»: какие состояния
  мозга набились (`citizen:shop`, `idle`, `queue`…). Так нашлась вечерняя толпа у закрытого магазина ТС: 86 человек
  в `shop` и 56 в `idle` — голодные ходили к закрытой двери по кругу. Толпа в одном состоянии — почти всегда петля
  решения, а не «популярное место». Задержанные в КПЗ Управы считаются отдельно — они не толпа.
- **Самая людная ячейка жителей** — главная цифра толпы; общий пик часто дают ВС (построение в Управе) — смотри, где
  он, прежде чем писать о толпе.
- `worldstats`: «Стоят на месте 30 с» и «„Идут“, но стоят» — застрявшие; «голодают (0)» — еда не доходит;
  «Кто кого» — неожиданные пары (ВС → горожанин, армия → мирные) — повод разобраться.
- Одна картинка и один сид — ещё не вывод: важные цифры проверь на втором сиде (`SEED=7919`, `SEED=6`) и перед
  записью в CLAUDE.md укажи сид, минуты и условия, как в существующих «Замер …».
- Короткие прогоны (`MIN` 1–3) годятся проверить, что скрипт работает: они видят только утро. Выводы о сутках, о
  вечерней толпе — 12+ минут и `SCALE=4`.
