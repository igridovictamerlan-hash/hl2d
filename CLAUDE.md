# CLAUDE.md — Верхнеречье

Браузерная 2D-игра с видом сверху в духе ролевых серверов: оккупированный город у ГЭС, тесные переулки под
контролем Протектората (лор — `LORE.md`, вводная в меню — `INTRO` в `config/menus.ts`). Все персонажи — пешки (пиксельные в своём стиле или прежние «фасолины» RimWorld — выбор в меню «Пешки»; цвет формы по рангу) с подписью имени/роли. Игрок управляет одним,
остальные — NPC, ведущие себя как игроки RP-сервера.

**Язык:** интерфейс, комментарии и документация — по-русски; идентификаторы в коде — по-английски.

## Свой мир вместо HL2 (названия)
Игрок видит только названия своего мира; внутренние идентификаторы в коде остались прежними (так
меньше правок и сохранения не ломаются). Новые тексты пишите в новых названиях:

| В коде (id, тип) | Игрок видит |
|---|---|
| город, `Сити-17` в старых сохранениях | Верхнеречье |
| `Alliance`/`combine`, `authority` | Протекторат |
| `cp` (силовой блок) | Внутренняя стража, кратко «ВС» (позывные `ВС-1234`) |
| `ota`, `OtaBrain`, `ota_alpha`/`ota_king` | Легион: легионер `LGN.ALPHA`, претор `LGN.PRAETOR` |
| `cwu` | Трудовой союз (ТС) |
| `vort`, `vort_slave` | поднадзорные: серая роба с номером, ошейник-маячок (`PAWN.outfits.vort.convict`) |
| `admin` | Комендант |
| зона `nexus`, POI `nexus_*` | Управа (женский род: «Управа захвачена») |
| «Цитадель» (откуда корабли) | ГЭС («с ГЭС», «на ГЭС») |
| HYDRA (`elite`, `hydra_*`) | спецотряд «Гроза», нашивка-молния (`O.lambda` — её цвет) |
| `ar2` (`pulse`) | импульсная винтовка Легиона «ИВЛ» |
| `cremator` | Санитар |
| `cid`, `law.hasCid`, `fake_cid`, причина `no_cid` (`Character.passport`) | паспорт: «проверка документов», «нет паспорта», «поддельный паспорт» |
| юниты ВС `rct`, `pcu3`…`ofc`, `su1`…, `epu` (`CP_RANKS`) | должности: рекрут, патрульный, сержант, офицер, следователь, медик, спецназ… — кодов вида PCU.03 / SU.01 игрок не видит |

## Команды

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # все тесты vitest (~12 мин на 4 ядрах) — перед пушем или в CI
npm run test:fast  # быстрый набор (~70 с, 200 тестов): генератор, A*, коллизии, бой, реакции города, интерфейс — после каждой правки
npx vitest run tests/war   # тесты одной системы — по имени файла
npm run typecheck  # tsc для src и tests
npm run build      # typecheck + сборка в dist/
npm run mapstats   # метрики генератора по 30 сидам (DEBUG_GEN=1 — причины отбраковки попыток)
npm run worldstats # аудит живого мира: MINUTES игровых минут города (SEED; RELATIONS=0 — без живых людей; HOODS=0 — без районной жизни; CP=classic — прежняя карта аудитов, иначе типы КПП по сиду, как в игре; LINE=0 — без линии армии; DUGOUTS=0 — без логики передовых блиндажей; WARCFG="dugout.sortie.chance=0,line.shift=300" — подмена чисел `WAR` на прогон) — смерти, еда, деньги, занятия, застрявшие, связи и настроение, фронт (выстрелы и потери у КПП, линия, блиндажи)
```

Параметры адреса: `?seed=123` (карта по seed, пишется в адрес автоматически), `?map=city17`
(загрузить `public/maps/city17.json`), `?npcs=40` (ровно столько граждан — в обход «Населения города» в меню), `?debug=1`, `?mode=squad&side=rebel|combine`
(экспериментальный режим «отряд на отряд»), `?touch=1` (сенсорное управление и с мышью).

## Стек и почему без движка

TypeScript + Vite + HTML5 Canvas 2D, без игровых движков. Всё ключевое здесь нестандартное —
генератор переулков, туман войны лучами, A* по якорям 2×2 с учётом радиуса, уступание дороги;
Phaser не дал бы готового для этого, а добавил бы свой цикл, сцену и физику, с которыми пришлось бы
бороться. Логика не зависит от DOM и целиком тестируется в Node (vitest), включая безголовую
симуляцию NPC (`tests/simHarness.ts`).

## Архитектура (кратко; полное дерево и тик логики — `docs/architecture.md`)

```
src/
  main.ts       точка входа, параметры адреса
  dev/          листы ассетов для просмотра в браузере (`npm run dev` → `/sheets/…`)
  config/       ВСЕ настраиваемые значения — никаких «магических чисел» в коде
  core/         Game (корень: системы, update/render), GameLoop (60 Гц + интерполяция), Input, PlayerController, Camera, EventBus, Rng
  world/        GameMap, tiles, NavGrid (якоря 2×2), collision, visibility, туман, свет, отрисовка карты, мебели и зданий
    generator/  CityGenerator и его этапы: макроплан, решётка, штампы зданий, КПП, улицы, ряды домов, пустошь, канализация
  entities/     Character (игрок и NPC — один класс), инвентарь, физика, пешки и оружие (отрисовка, походка, позы)
  ai/           A*, PathService, Mover, Gunner, Tactics, MeleeFighter; brains/ — мозги по ролям (CitizenBrain, CpBrain, RebelBrain…)
  systems/      игровые системы: закон, экономика, бой, война, подполье, склад, тюрьма, банды, рация, отношения… (по файлу на систему)
  ui/           DOM поверх холста: HUD, меню, панели, карта, звук, сенсорное управление
tests/          vitest; simHarness.ts — мир без DOM (`makeSim`) для тестов поведения
public/maps/    сохранённые карты (JSON), открываются через ?map=имя
```

Системы живут в `AiContext` (`ai/AiContext.ts`, поле `ctx.<система>`), создаются в `Game` и в `tests/simHarness.ts`
(новую систему — в оба места). Порядок тика — `Game.update`.
## Ключевые понятия
- **Тайл** 16 px. Город 480×270 тайлов (7680×4320 px): оба пограничных КПП — у западной стены, от каждого
  на восток — свой проспект (северный и южный, ~400 тайлов до восточной стены), их пересекает поперечная
  магистраль у площади. С запада на восток — три полосы достатка (Слобода, Старый город, Верхний город за стеной,
  см. «Генератор», 1). С запада — предгорья (40 тайлов: тропа, лагерь сопротивления), с севера и юга — хребты
  долины (по 13 рядов скал), с востока — кромка в 3 тайла, за ней ГЭС с водохранилищем и речным портом (130 тайлов, см. «Генератор», 8б) —
  653×296; справа за зазором — канализация (масштаб 1:2), вся карта ~984×296. Типы — `world/tiles.ts` (`solid`, `opaque`, символ для JSON).
  Добавляя тип, допишите его в `TILE_DEFS`, палитру `MapRenderer` и `DevPanel`.
- **Уровни** (`Level`: city / sewer) — две области одной сетки без прохода между ними; связь только
  люками. `GameMap.underground` (прямоугольник канализации по её зонам), `levelAt`, `levelBounds`;
  `NavGrid.level` по якорям. A* между уровнями сразу отказывает, `randomAnchorAround` берёт цели
  только на своём уровне, камера не выходит за границы уровня, в канализации обзор короче
  (`VISION.sewerRadius`), выстрелы с другого уровня не слышны.
- **Якорь 2×2**: персонаж радиусом 12 px занимает квадрат 2×2 тайла. Якорь (ax, ay) ↔ центр в
  ((ax+1)·16, (ay+1)·16). Связность карты, A* и поиск «карманов» работают по якорям — поэтому
  проход 2 тайла (32 px) пропускает ровно одного, 3 тайла (48 px) — двоих.
- **Зоны** — сетка `zoneGrid` (id зоны на тайл) + список `zones` (kind + имя). `ZoneKind`:
  residential, avenue, plaza, nexus, cells, industrial, restricted, checkpoint (пограничные КПП),
  outlands (пустоши за стеной), shop (магазин ТС, лавки и кафе проспекта — у каждой своя зона с
  названием), sewer, rebel_base (убежище), black_market, cwu_hq (штаб ТС), arsenal (склад Протектората),
  canteen (общая столовая), prison (тюрьма Протектората), academy (академия ВС).
- **Точки интереса (POI)** — `map.pois` в координатах тайлов: лагерь сопротивления и его тайник, окно раздачи, центр площади, терминал
  найма, ворота и стойка Управы, терминал кодов тревоги, камеры КПЗ, ворота запретной зоны, заводские дворы, посты часовых
  КПП, выходы в пустоши, люки (`hatch` в городе / `sewer_hatch` в канализации: якорь 2×2, x,y — его
  левый верхний тайл; пары связаны одинаковым `id`), убежище, тайник, прилавок и место торговца, передовые блиндажи повстанцев
  (`dugout` — пол и `face` входа, `dugout_cache` — ящик, `dugout_bunk` — места отдыха).
- **Двери** — группы соседних тайлов `DOOR`. Состояние (закрыта/заперта) живёт в `GameMap.doorClosed/
  doorLocked`: закрытая перекрывает обзор (`isOpaque`), запертая — ещё и проход (`isSolid`).
  Запирание вызывает `NavGrid.refresh` вокруг двери.
- **Видимость**: `visibility.ts` — луч DDA до первого непрозрачного тайла. Игрок видит в радиусе
  `VISION.radius`; NPC — в `VISION.npcRange` с углом обзора `npcFovDeg` (вплотную — во все стороны).
  Одни и те же функции для игрока и NPC: от ВС можно скрыться за поворотом или за дверью.
- **Фракции и ранги** — `config/factions.ts`. Цвет формы пешки по рангу (`colorsOf`): ВС от голубого
  (RCT) до тёмно-синего (DvL). У сопротивления юнит — по профессии (`REBEL_RANKS`, `rebelUnitOf`,
  `REBEL_UNIT`; `rank` = номер юнита, HP — `roleHp`): армия — жёлтые ники, глава Патрик и HYDRA
  (`elite`) — красные. Рубаха армии синяя, жилет — с солдата.
  `authority` — кто проверяет, а не проверяется (ВС, OTA, комендант).

## Соглашения
- Все числа, цвета, скорости, зарплаты и т.п. — в `src/config/*`. Новый параметр → в конфиг.
- `src/` не использует API Node; `tests/` может (свой `tests/tsconfig.json`).
- Случайность в генерации и мире — только через `Rng` (seed), не `Math.random` (кроме выбора нового seed).
- Логика не трогает DOM; UI подписывается на `EventBus`. Новые события — в `GameEvents`.
- Персонаж игрока и NPC — один класс `Character`; различие только в источнике управления.
- Отрисовка тайлов — в экранных пикселях с округлением (без щелей); подписи — в экранных пикселях.
- Перед коммитом: `npm run typecheck && npm run test:fast` плюс тесты затронутых систем (`npx vitest run tests/<система>`).
  Полный `npm test` (~12 мин) — перед пушем крупной работы; на GitHub его гоняет CI (`.github/workflows/ci.yml`).
- Тесты детерминированы: `makeSim` сбрасывает общий набор номеров CID (`resetCids`), иначе случайность
  теста зависела бы от предыдущих тестов файла.
- Новая фича — коротко в `docs/history.md` (что и зачем, замеры), подробности — в файле системы в `docs/`.

Работа строго поэтапно: после каждого этапа — отчёт и ожидание подтверждения пользователя.
